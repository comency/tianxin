# 全模块本地启动设计

> 文档作用：定义芋道源码 JDK 25 分支的本地全模块编译、数据初始化、前后端启动与验证边界。
>
> 作者：DAMU
>
> 创建时间：2026-07-22

## 1. 目标与边界

在 Windows 本机启动 `ruoyi-vue-pro` 的所有后端业务模块，并使用 Vue3 管理后台访问对应菜单和页面。
本次目标是使应用、动态菜单、基础接口和数据库模块正常运行；不配置真实第三方业务凭据。

本次启用的模块包括：会员、工作流、报表、公众号、支付、商城、CRM、ERP、AI、IoT、MES、WMS、IM，
以及原有的系统与基础设施模块。

AI 模型服务、向量数据库、IoT 时序数据库与网关、IM 实时音视频、支付渠道、微信公众号和小程序均采用
“未配置不阻塞启动”的策略。对应页面可以访问；需要真实外部服务的操作在后续单独配置凭据和服务地址后启用。

## 2. 已确认环境

| 项目 | 本地约束 |
| --- | --- |
| JDK | `D:\jdk-25.0.2`，启动命令和脚本必须显式使用该目录 |
| Maven | Apache Maven 3.9.15 |
| Node.js | v22.18.0 |
| MySQL | MySQL 8.4，账号 `root`，密码 `root` |
| Redis | 已安装，启动前应确认服务端可连接 |
| 后端端口 | `48080` |
| 数据库 | `ruoyi-vue-pro`，允许备份、重建与导入 |

当前运行 Codex 的进程仍可能持有旧版环境变量，因此不能依赖继承的 `JAVA_HOME` 或 `Path`；
所有构建和运行命令必须在进程内先设置 `JAVA_HOME=D:\jdk-25.0.2` 并将其 `bin` 放在 `Path` 首位。

## 3. 架构与装配

后端入口为 `yudao-server`，`YudaoServerApplication` 扫描 `cn.iocoder.yudao.server` 和
`cn.iocoder.yudao.module`。根 `pom.xml` 控制 Maven Reactor 模块，`yudao-server/pom.xml` 控制
最终 Spring Boot Jar 的业务依赖；两处均需一致启用所有业务模块。

```text
Vue3 管理后台
    |
    | HTTP /admin-api
    v
yudao-server :48080
    |
    +-- 系统、基础设施、会员、BPM、报表、公众号、支付、商城
    +-- CRM、ERP、AI、IoT、MES、WMS、IM
    |
    +-- MySQL 8.4：全部基础数据和业务表
    +-- Redis：缓存、登录令牌、分布式锁
    `-- 可选外部服务：本阶段禁用其自动装配或连接初始化
```

商城由 `yudao-module-mall` 聚合 `product`、`promotion`、`trade`、`statistics` 子模块，IoT 由
`yudao-module-iot` 聚合 `iot-biz`、`iot-core`、`iot-gateway`。根聚合模块和 Server 依赖必须同时启用，
以保证 Maven 能解析所有传递依赖并使组件扫描发现业务 Bean。

## 4. 数据库设计

初始化前先使用 MySQL 客户端导出当前 `ruoyi-vue-pro` 数据库到带时间戳的 SQL 备份文件。随后删除并重建
同名数据库，使用 UTF-8 字符集和 `utf8mb4` 排序规则。

导入顺序固定为：

1. `sql/mysql/ruoyi-vue-pro.sql`，提供系统、基础设施与公共基线表、菜单和字典数据。
2. `sql/mysql/quartz.sql`，提供 Quartz 持久化表。
3. 每个业务模块的最新可用 SQL 增量包，按模块和发布日期选择唯一最新文件；需要先解压再导入。
4. 对所有模块 SQL 执行结果进行复核，确认无失败语句，并检查各模块菜单、权限和核心表存在。

不能将同一模块的多个历史增量包全部重复导入。基础 SQL 已包含部分历史状态，重复导入会产生主键冲突或重复
数据；每个模块仅选择与当前源码版本匹配的最新数据包。名称中含有“传播违法”是仓库文件名，不代表应自动执行
其中每个历史版本，实际选择应以源码发布版本与 SQL 内容校验结果为准。

## 5. 配置设计

新增独立的本地全模块 profile，不修改现有 `application-local.yaml` 的默认轻量启动语义。

该 profile 使用 `root/root` 连接 MySQL，连接 `127.0.0.1:6379` Redis，并保留服务器端口 `48080`。
配置应明确排除或关闭以下可能在应用启动阶段建立外部连接的能力：

- AI 的 Qdrant、Milvus、Redis 向量库自动配置及未提供密钥的模型客户端。
- IoT 的 TDengine 数据源和需要 MQTT、设备网关的连接初始化。
- IM 的 LiveKit 或其他音视频服务连接。
- 支付、微信公众号、小程序和第三方登录的真实回调与凭据校验。
- RocketMQ、RabbitMQ、Kafka 等未在本机运行的消息中间件客户端。

保留业务模块自身的 Spring Bean、数据库访问、权限菜单和 REST Controller。某项操作依赖未配置的外部服务时，
应由模块现有的配置校验或业务异常返回明确错误，不能因为缺少地址、密钥或服务进程而使应用整体启动失败。

## 6. 前端设计

现有 `yudao-ui/yudao-ui-admin-vue3` 目录只保留 MES 页面和 API 文件，缺少 `package.json`、Vite 配置、
路由、状态管理和基础组件，不能单独构建。

应拉取官方 `yudao-ui-admin-vue3` 的完整 Vue3 + Element Plus 工程作为基线，并将当前目录保留的文件合并为
覆盖层。合并前后须比较同路径文件；仅在当前文件确实是本地定制版本时覆盖，避免将不完整文件覆盖到基线工程。

不使用 RuoYi-Vue 的 `ruoyi-ui` 作为运行前端：该工程基于 Vue2、Vue CLI 和 Element UI，与目标 Vue3 工程及
芋道的接口、权限菜单和业务页面不兼容。RuoYi-Vue 仅可作为旧版目录结构和基础配置的参考。

前端开发服务器通过代理将 `/admin-api` 转发到 `http://127.0.0.1:48080`。生产构建产物由静态 Web 服务器托管，
并将该路径反向代理到后端服务。

## 7. 验证与验收

验证分为四层，全部通过才视为本次启动完成：

1. 环境层：命令解析出的 Java 为 25.0.2，MySQL 与 Redis 可连接，前端依赖可安装。
2. 构建层：根 Maven Reactor 在所有业务模块启用后通过编译与测试，前端通过生产构建。
3. 服务层：Spring Boot 日志显示端口 `48080` 已监听；健康端点、登录接口与 Swagger 可访问。
4. 业务层：管理员登录后，动态菜单中可看到所有启用模块；逐一打开模块列表页且不存在前端路由错误、接口 404、
数据库表不存在或 Bean 缺失。

若构建失败或服务无法启动，先保留失败日志并按照模块、依赖和外部连接三类定位。不得通过删除模块依赖、跳过
模块 SQL 或把外部服务异常静默吞掉来伪造“全模块启动”结果。

## 8. 安全与回退

本地 profile 不提交真实第三方密钥、支付私钥或生产回调地址。现有示例密钥和 URL 不作为可用凭据。

数据库回退方式为恢复启动前的时间戳备份；配置回退方式为恢复根 `pom.xml` 与 `yudao-server/pom.xml` 的
注释状态，并删除新增的全模块本地 profile。前端回退方式为恢复合并前的残留源文件备份。
