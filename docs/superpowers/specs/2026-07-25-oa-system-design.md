# OA 系统建设方案

> 文档作用：定义在现有 RuoYi-Vue-Pro 项目中建设行政人事协同 OA 系统的架构、功能边界、菜单、流程和验收标准。

## 1. 建设目标与范围

本期建设面向制造、销售、服务型企业的单企业多部门 OA 系统，优先解决行政人事协同问题。系统以统一工作台为入口，覆盖人事、假勤、行政协同、审批、费用、采购申请和任务协作。

本期不建设集团多组织、子公司隔离、跨法人审批、共享服务中心与跨法人报表。后续若扩展集团化，必须新增组织主体、法人、核算主体与跨组织授权模型，不能仅通过部门树模拟。

OA 的职责是处理人员和办公协同。ERP、CRM、MES、WMS、IM、BPM 保持各自领域主数据和业务事实的唯一来源，OA 不复制这些模块的核心数据。

## 2. 目标架构

### 2.1 模块划分

新增后端 Maven 模块 `yudao-module-oa`，新增前端目录 `yudao-ui/yudao-ui-admin-vue3/src/views/oa` 与 `src/api/oa`，由 `yudao-server` 装配并对外提供管理端接口。

OA 模块按以下领域拆分包和页面，避免将行政、人事、费用、资产等业务堆叠到单一服务中：

| 领域 | 模块职责 | 核心业务实体 |
| --- | --- | --- |
| 工作台 | 聚合个人待办、提醒和快捷入口 | 工作台卡片、提醒聚合记录 |
| 人事组织 | 管理员工扩展档案与异动 | 员工档案、入转调离单、合同证照 |
| 假勤 | 维护规则、考勤记录、余额和异常 | 班次、日历、打卡、假期余额、考勤月报 |
| 行政协同 | 管理公告、会议、日程、车辆和用品 | 会议室、会议、日程、车辆、用品台账 |
| 审批业务 | 保存申请单据并关联 BPM 流程 | 各类 OA 申请单、流程关联记录 |
| 费用预算 | 管理报销、借款、预算占用与 ERP 交接 | 报销单、借款单、预算、交接记录 |
| 采购资产 | 管理采购申请和资产使用协同 | 采购申请、资产领用、归还、调拨、盘点 |
| 协同执行 | 管理任务、会议决议和后续项目协同 | 任务、评论、附件、会议纪要 |
| 报表设置 | 配置基础数据、集成及分析口径 | 编号规则、类型字典、集成任务、统计快照 |

### 2.2 平台能力复用

| 平台能力 | 主数据或事实来源 | OA 集成方式 |
| --- | --- | --- |
| 用户、部门、岗位、角色、数据权限 | System | OA 只保存用户标识、部门标识等引用，不复制组织资料 |
| 审批流程、任务、意见、抄送 | BPM | OA 创建业务单据后启动流程，流程结束事件回写业务状态 |
| 待办、已办、我发起、抄送 | BPM | OA 工作台聚合数量和深链，审批详情跳转或嵌入 BPM 任务 |
| 公告、站内信 | System | 复用公告和通知模板，补充 OA 业务范围与已读回执 |
| 即时沟通 | IM | 从人员、任务、会议和审批详情跳转 IM 单聊或群聊 |
| 采购、付款、入库、凭证 | ERP | OA 只发起受控交接，ERP 是财务与供应链凭证的唯一来源 |
| 客户、商机、客户合同 | CRM | OA 按标识引用 CRM 主数据，不复制客户档案 |
| 生产排班和设备信息 | MES、IoT | OA 只消费结果做人员提醒，不替代生产和设备管理 |

### 2.3 领域边界

每个领域只保留一个权威来源。OA 单据状态由 OA 管理，流程节点状态由 BPM 管理，财务或供应链执行状态由 ERP 管理。任何一方不得直接覆盖其他领域的状态。

所有需要留痕、撤回、催办、多级审批或抄送的申请，均先创建 OA 业务单据，再通过 BPM 发起流程。审批完成后，使用流程监听器或领域事件更新 OA 单据；涉及 ERP 的动作，再创建可审计、可重试的交接记录。

| OA 设置 | 编号与基础配置 | 单据编号、费用类型、假期类型、班次、会议室、车辆、用品和资产分类 | 首期 |
| OA 设置 | 审批映射 | 业务类型与 BPM 流程模型绑定、金额阈值、部门负责人和预算校验规则 | 首期 |
| OA 设置 | 集成配置 | 考勤、ERP、CRM、IM、对象存储接口配置及失败重试记录 | 第二期 |

权限遵循 `oa:<领域>:<动作>`，例如 `oa:attendance:query`、`oa:expense:create`、`oa:asset:transfer`、`oa:budget:manage`。审批任务操作继续使用 BPM 权限。OA 数据范围复用现有本人、本部门及以下、指定部门、全部范围；费用、预算和资产再校验责任人及所属部门。

首期“发起申请”中的用车、用印和合同仅提供基于通用表单和 BPM 的申请入口，不包含车辆派车、印章借还、合同履约及台账等专属管理能力。对应的主数据、专属页面和执行台账统一在第二期交付。

## 4. 首期交付范围

首期必须完成以下可闭环能力：

1. OA 工作台及与 BPM、System、IM 的聚合入口。
2. 员工档案、入转调离、假勤规则、考勤异常和假期余额。
3. 公告、通讯录、日程、会议和任务。
4. 请假、加班、出差、补卡、外出、报销、借款、采购申请、用车、用印、合同等审批入口。
5. 费用报销、借款、采购申请的 BPM 流程关联与流程结果回写。
6. 已通过报销、借款、采购单据到 ERP 的幂等交接、失败重试与状态回写。
7. OA 基础配置、审批映射、权限菜单与操作审计。

第二期建设预算、车辆、办公用品、固定资产、合同印章、报表和集成配置。第三期建设项目协同和知识文档。第二期、第三期功能不得作为首期验收阻塞项。

## 5. 关键流程和状态规则

### 5.1 假勤申请

员工创建请假、加班、出差、补卡或外出单据后，OA 校验余额、时间重叠、班次和必填附件，再创建 BPM 流程实例。业务单据状态为草稿、审批中、已通过、已驳回、已撤回和已作废。

仅在流程最终通过时，系统更新假期余额、考勤异常或调休台账。审批中单据不可重复占用额度；驳回、撤回或作废时释放预占额度。流程实例编号必须写入业务单据，以供全链路追踪。

### 5.2 费用与借款

报销单必须包含费用类型、金额、发生日期、费用明细、分摊信息和规定的附件。提交前校验金额、预算余额、发票附件与重复报销规则。借款核销必须关联已付款借款及可核销余额。

流程通过后，创建状态为待推送 ERP 的交接记录。每次交接使用唯一幂等请求号。ERP 成功后回写付款状态、付款时间和凭证号；失败后记录失败原因、请求报文摘要、重试次数和下一次重试时间。重试不得生成重复财务单据。

### 5.3 采购与资产

采购申请先校验物品明细、申请部门、预算和审批映射。审批通过后仅向 ERP 创建采购订单草稿，采购、收货、付款与供应链凭证继续由 ERP 管理。

固定资产卡片以 ERP 或入库确认结果为准创建或同步，OA 管理领用、归还、调拨、盘点和离职交接。离职流程完成前必须检查未归还资产、未完成任务和待处理审批。

### 5.4 会议与任务

会议预约校验会议室、参会人和时间冲突。会议纪要可以拆分为任务。任务状态固定为未开始、进行中、已完成、已关闭和已逾期。定时任务仅提醒负责人和上级，不自动关闭逾期任务。

## 6. 异常处理和审计

| 异常场景 | 处理规则 |
| --- | --- |
| 审批人离职、无权限或不存在 | 发起前校验；运行中进入异常待办，由流程管理员按 BPM 能力改派 |
| ERP 或考勤接口超时、失败 | 保存幂等请求号、失败原因、重试次数和调用日志；人工重试前阻止重复推送 |
| 预算并发占用或不足 | 创建时预占；驳回、撤回时释放；通过后转正式占用 |
| 附件不可访问或丢失 | 提交和查看均校验文件存在性、业务归属与数据权限 |
| 离职存在未交接事项 | 离职流程前置校验资产、任务、待办和借款，未清理不得完成离职 |

所有 OA 单据保留创建人、创建部门、当前状态、流程实例编号、版本号、创建时间、修改时间和操作日志。集成记录保留来源单据、目标系统、幂等键、请求摘要、响应摘要、状态、重试次数和最后失败原因。敏感信息和附件访问必须遵守现有角色与数据权限。

## 7. 验收标准与测试范围

### 7.1 业务验收

1. 每个首期申请类型均可创建草稿、提交、审批、驳回、撤回、催办和查询历史。
2. 审批最终结果能正确回写 OA 单据，并在请假、加班、补卡和外出等场景准确更新假勤台账。
3. 费用、借款和采购申请在流程通过后只能生成一条 ERP 交接记录；多次重试不产生重复单据。
4. 会议可完成预约、冲突校验、签到、纪要和任务拆分；任务可提醒、更新和关闭。
5. 员工离职无法绕过资产、任务、审批和借款交接校验。
6. 菜单、按钮、人员范围和业务数据均按角色与数据范围生效。

### 7.2 技术测试

1. 为每个领域服务编写单元测试，重点覆盖状态转换、余额与预算占用、幂等和权限校验。
2. 为 BPM 监听器和 ERP 交接编写集成测试，模拟成功、超时、失败、重复回调和人工重试。
3. 为首期页面编写关键交互测试，覆盖申请提交、流程跳转、附件、列表筛选和数据权限。
4. 执行模块编译、后端测试、前端类型检查与首期主流程的人工验收。

## 8. 实施约束

1. 业务单据使用明确的领域表，不将业务字段塞入 BPM 表单 JSON 作为唯一存储。
2. 业务模块不直接修改 System、BPM、ERP、CRM、MES 或 IM 的内部表。
3. 所有跨模块写入通过公开服务、领域事件或受控接口完成，并具备幂等和审计能力。
4. 代码、SQL、页面和接口文案统一使用 UTF-8 编码；新增文件遵循项目既有的 Java、Vue 和 TypeScript 分层规范。
5. 实施前必须将首期每种申请对应的 BPM 模型、办理人规则、表单字段、附件要求与 ERP 交接字段逐项配置并测试。
