# CMS 多渠道内容管理系统设计

> 文档作用：定义 RuoYi-Vue-Pro 多渠道 CMS 的模块边界、菜单权限、数据模型、发布流程与实施范围。
>
> 作者：DAMU
>
> 创建时间：2026-07-25
>
> 核心功能：内容一次生产、栏目级 BPM 审批、跨渠道编排发布、投放回执和效果分析。

## 1. 背景与目标

当前项目是 RuoYi-Vue-Pro 多模块单体，已有系统、基础设施、会员、商城、公众号、工作流、支付、报表等模块。
现有 `yudao-module-mp` 的职责是微信公众号运营，不能作为官网、H5、小程序、UniApp、App、邮件和短信的通用内容主数据。

本方案新增独立的 `yudao-module-cms`，实现“内容一次生产，多渠道编排与发布”。CMS 以内容为唯一主数据，公众号仅作为发布渠道之一。

系统首期目标渠道按优先级为：官网/H5、微信公众号、小程序、商城 UniApp、App 推送、邮件和短信。
所有内容审批接入既有 BPM 模块，由栏目配置流程定义，避免 CMS 重复建设审批引擎。

## 2. 架构与模块边界

### 2.1 工程接入

- 新增后端模块：`yudao-module-cms`。
- 在根 `pom.xml` 和 `yudao-server/pom.xml` 中注册 CMS 模块。
- 管理后台目录：`yudao-ui/yudao-ui-admin-vue3/src/views/cms`。
- 管理端接口前缀：`/admin-api/cms`。
- 官网/H5、小程序、商城 UniApp 的公开读取接口前缀：`/app-api/cms`。

### 2.2 责任边界

CMS 负责栏目、内容、内容版本、专题、标签、内容模板、SEO、素材引用、审批关联、渠道版本、发布计划、发布任务、回执和统计数据。

渠道不能直接修改 CMS 内容。审核通过后，CMS 将不可变内容版本拆分为渠道任务，由统一的 `CmsChannelPublisher` 适配器执行。

| 既有模块 | CMS 集成方式 | 边界 |
| --- | --- | --- |
| `infra` | 文件、定时任务、缓存、操作日志 | CMS 仅保存文件引用，不复制文件。 |
| `system` | 用户、部门、字典、消息、邮件、短信、租户、权限 | CMS 不保存敏感渠道凭据。 |
| `bpm` | 栏目级审批流程、待办、审批回调 | CMS 保存流程实例和业务状态，不实现流程引擎。 |
| `member` | 会员标签、人群圈选 | CMS 保存圈选规则与快照，不复制会员资料。 |
| `mall` | 商品、分类、活动链接 | CMS 仅保存外部对象引用，不复制商品数据。 |
| `mp` | 公众号草稿、微信发布、发布回执 | `mp` 仅承担公众号渠道发布，不承担 CMS 内容主数据。 |

### 2.3 渠道发布方式

| 渠道 | 发布方式 | 发布结果 |
| --- | --- | --- |
| 官网/H5 | 公开内容 API，前端按路由渲染 | 内容、SEO、站点地图和缓存更新。 |
| 小程序 | 公开内容 API，小程序按内容类型展示 | 内容及跳转路径生效。 |
| 商城 UniApp | 公开内容 API，支持关联商品和活动 | 内容卡片和商品导流生效。 |
| 微信公众号 | 调用既有 `mp` 草稿和发布能力 | 草稿素材、微信文章链接、发布状态。 |
| App 推送 | 推送服务适配器投放 | 任务回执、到达和点击数据。 |
| 邮件/短信 | 复用系统邮件和短信能力 | 发送回执、失败原因、点击追踪。 |

首期不建设独立官网、小程序或 App 客户端，只建设稳定的内容 API、路由约定与渠道发布能力。

## 3. 菜单、功能与权限

新增一级菜单 `CMS 内容管理`，建议排序在“公众号”之后、“商城”之前。

```text
CMS 内容管理
├─ 工作台（cms:dashboard:query）
├─ 内容生产
│  ├─ 内容管理（cms:content）
│  ├─ 内容审核（cms:content-audit）
│  ├─ 内容版本（cms:content-version）
│  ├─ 栏目管理（cms:category）
│  ├─ 专题管理（cms:topic）
│  ├─ 标签管理（cms:tag）
│  ├─ 内容模板（cms:template）
│  └─ 素材引用（cms:asset）
├─ 发布运营
│  ├─ 发布编排（cms:publish-plan）
│  ├─ 发布任务（cms:publish-task）
│  ├─ 定时发布（cms:publish-schedule）
│  ├─ 投放人群（cms:audience）
│  └─ 投放记录（cms:delivery-record）
├─ 渠道管理
│  ├─ 站点与 H5（cms:site）
│  ├─ 小程序渠道（cms:channel-miniapp）
│  ├─ 商城 UniApp 渠道（cms:channel-uniapp）
│  ├─ 微信公众号渠道（cms:channel-mp）
│  ├─ App 推送渠道（cms:channel-app）
│  └─ 邮件短信渠道（cms:channel-message）
├─ 数据中心
│  ├─ 内容分析（cms:analytics-content）
│  ├─ 渠道分析（cms:analytics-channel）
│  └─ 投放分析（cms:analytics-delivery）
└─ 系统设置
   ├─ 内容类型（cms:content-type）
   ├─ 审批流程绑定（cms:workflow）
   ├─ SEO 与路由规则（cms:seo）
   ├─ 敏感词与发布规则（cms:rule）
   └─ 发布回调与重试（cms:callback）
```

| 工作域 | 页面 | 核心功能 |
| --- | --- | --- |
| 工作台 | 工作台 | 待编辑、待审核、待发布、失败任务、渠道成功率、阅读趋势与快捷创建。 |
| 内容生产 | 内容管理 | 富文本、图文、视频、图集、外链、商品导购；草稿、预览、复制、提审、撤回、归档和删除。 |
| 内容生产 | 内容审核 | 内容维度查询流程状态、审批节点和意见；跳转 BPM 待办处理。 |
| 内容生产 | 内容版本 | 版本快照、版本比较、历史恢复；线上内容通过修订版更新。 |
| 内容生产 | 栏目/专题/标签 | 栏目树、编辑授权、默认模板、默认渠道、排序、专题聚合与标签检索。 |
| 内容生产 | 内容模板/素材引用 | 内容骨架、默认 SEO、可用渠道；查询素材被内容和版本引用的关系。 |
| 发布运营 | 发布编排 | 同一审批版本的多渠道标题、摘要、封面、正文片段、跳转地址与发布时间配置。 |
| 发布运营 | 发布任务/定时发布 | 任务状态、单渠道重试、取消、回执、任务调度和版本校验。 |
| 发布运营 | 投放人群/记录 | 会员圈选、规模快照、投放结果、点击数据和退订处理。 |
| 渠道管理 | 站点和终端渠道 | 域名、路由、导航、推荐位、站点地图、账号映射、跳转规则、渠道启停。 |
| 渠道管理 | 消息渠道 | 推送服务引用、模板、频控、退订策略和发送时段。 |
| 数据中心 | 内容/渠道/投放分析 | 阅读、分享、转化、成功率、失败类型、发送到达点击漏斗与导出。 |
| 系统设置 | 内容类型/流程/规则 | 字段模型、流程绑定、URL、SEO、敏感词、频控、重试和回调签名。 |

统一按钮权限示例：

- 内容管理：`cms:content:query`、`cms:content:create`、`cms:content:update`、`cms:content:submit`、`cms:content:withdraw`、`cms:content:archive`、`cms:content:delete`、`cms:content:export`。
- 发布任务：`cms:publish-task:query`、`cms:publish-task:create`、`cms:publish-task:execute`、`cms:publish-task:cancel`、`cms:publish-task:retry`、`cms:publish-task:revoke`。

## 4. 核心数据模型

所有 CMS 业务表继承既有租户、创建人、创建时间、更新人、逻辑删除字段。

| 数据对象 | 建议表名 | 职责 |
| --- | --- | --- |
| 站点 | `cms_site` | 官网/H5 站点、域名、语言、状态和默认 SEO。 |
| 栏目 | `cms_category` | 栏目树、默认内容类型、默认渠道、可编辑角色和 BPM 流程绑定。 |
| 内容 | `cms_content` | 内容稳定标识、栏目、当前草稿版本、当前线上版本和生命周期状态。 |
| 内容版本 | `cms_content_version` | 不可变快照，保存正文、封面、SEO、关联商品和审核发布字段。 |
| 专题、标签 | `cms_topic`、`cms_tag`、关联表 | 内容聚合和检索，不将标签 JSON 写入内容主表。 |
| 内容模板 | `cms_content_template` | 内容类型、字段模板、默认值和可用渠道。 |
| 内容素材引用 | `cms_content_asset_ref` | 内容版本与 `infra_file` 的引用关系和用途。 |
| 渠道配置 | `cms_channel`、`cms_channel_site` | 渠道启停、路由规则、账号或系统配置引用。 |
| 发布计划 | `cms_publish_plan` | 内容版本、目标人群、定时策略和整体状态。 |
| 发布计划渠道明细 | `cms_publish_plan_channel` | 每个渠道的标题、摘要、封面、正文片段、落地地址和发布配置。 |
| 发布任务 | `cms_publish_task` | 基于渠道明细生成的执行载荷快照、幂等键、外部单号、重试和错误信息。 |
| 人群规则/快照 | `cms_audience`、`cms_audience_snapshot` | 圈选规则、提交时规模快照和计算时间。 |
| 投放记录 | `cms_delivery_record` | App、邮件、短信批次、单人投放结果和退订状态。 |
| 审批绑定 | `cms_workflow_binding` | 栏目、内容类型和 BPM 流程定义的有效期映射。 |
| 统计事件/汇总 | `cms_analytics_event`、`cms_analytics_daily` | 原始阅读、点击、分享、转化事件和日汇总。 |

关键约束：内容版本不可更新；发布计划渠道明细只允许在任务创建前修改；发布任务按
`channel + content_version + publish_plan` 生成唯一幂等键；渠道敏感密钥仅引用系统配置或既有渠道配置；
外部对象仅保存模块、类型和对象编号引用。

## 5. BPM、发布与异常处理

### 5.1 内容状态

```text
草稿 -> 已提交审批 -> 审批通过 -> 待发布 -> 发布中 -> 已发布
  ^          |              |           |            |
  |          v              v           v            v
  └------ 已驳回         已撤回      部分成功      发布失败
                                            |
                                            v
                                         已撤回 / 已归档
```

- 内容主状态表示线上可用性；内容存在已发布版本时，即使新草稿正在审批，主状态仍保持“已发布”。
- 提审时冻结当前内容版本。审批期间的编辑只能产生新的草稿版本。
- 栏目根据有效的 `cms_workflow_binding` 发起 BPM 流程，并保存流程实例编号。
- BPM 回调使用流程实例编号和内容版本编号做幂等校验，只更新对应版本的审批状态。
- 审批通过后才允许创建发布计划；计划基于已审批的不可变版本拆分为多个渠道任务。
- 官网/H5、小程序和 UniApp 发布时切换公开版本并刷新缓存；公开接口仅返回已发布版本。
- 公众号、短信、邮件和推送撤回表示调用渠道允许的撤回能力或停止后续任务，不伪造外部内容已删除的状态。

### 5.2 任务失败

- 渠道超时、外部回调重复到达、定时任务重复执行均依赖幂等键保障不会重复投放。
- 单渠道失败不回滚其他成功渠道，发布计划标记为“部分成功”。
- 运营人员可仅重试失败渠道，保留全部请求、响应、重试次数和错误原因。
- 达到重试阈值后，任务进入人工处置队列；回调验签失败、版本失效、渠道停用等不可重试错误直接终止。

## 6. 分期实施

### 第一期：内容底座与审批闭环

实现站点、栏目、内容、内容版本、专题、标签、素材引用、栏目 BPM 绑定、后台内容页面、官网/H5/小程序/UniApp 公开 API、租户权限和操作审计。

### 第二期：发布编排与公众号

实现发布计划、渠道任务、定时任务、失败重试、公众号草稿与发布适配器、站点路由、SEO 和缓存刷新。

### 第三期：人群投放与消息渠道

实现会员人群规则、App 推送、邮件、短信适配器、频控、退订、投放回执和转化链接。

### 第四期：数据中心与运营增强

实现事件采集、聚合报表、导出、推荐位、A/B 内容版本；多语言和静态生成根据实际业务需求再引入。

## 7. 验收与测试

- 验证栏目权限、租户隔离、内容版本不可覆盖、BPM 提交、驳回、撤回和回调幂等。
- 为每个渠道适配器覆盖成功、超时、重复回调、局部失败、重试、撤回和操作审计场景。
- 验证公开 API 只返回已发布版本，缓存刷新后内容、路由和 SEO 一致。
- 端到端覆盖“创建内容 -> BPM 审批 -> 定时多渠道发布 -> 查询回执与分析”的完整闭环。
- 验证中文内容、标题、SEO、邮件和短信模板均使用 UTF-8 编码，避免跨渠道乱码。
