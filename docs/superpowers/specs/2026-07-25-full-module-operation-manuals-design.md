# 全模块操作手册设计

> 文档作用：定义全模块操作手册的范围、目录、内容标准与核验方式。
>
> 作者：DAMU
>
> 创建时间：2026-07-25

## 1. 目标与范围

为当前 RuoYi-Vue-Pro 全模块管理后台建立面向业务操作人员、系统管理员和实施人员的中文 Markdown
操作手册。文档保存于 `docs/`，按模块拆分，覆盖系统管理、基础设施、工作流、会员、支付、商城、
CRM、ERP、AI、IoT、MES、WMS、IM、报表和公众号模块。

手册以当前代码、动态菜单、前端页面和后端接口为事实来源，不将未实现或未配置的第三方能力描述为可直接使用。
需要支付渠道、AI 模型、物联网网关、微信公众号、实时音视频等外部服务的功能，必须标明配置前提。

## 2. 文档结构

在 `docs/` 创建以下文档：

| 文件 | 内容 |
| --- | --- |
| `README.md` | 阅读顺序、模块索引、适用角色和维护规则。 |
| `00-使用前准备与通用约定.md` | 访问、登录、权限、租户、列表查询、表单、新增编辑、导入导出、附件和审批等通用操作。 |
| `01-系统功能操作手册.md` | 系统管理与基础设施，包括用户、部门、岗位、菜单、角色、字典、配置、日志、文件、定时任务和代码生成。 |
| `02-ERP说明及操作手册.md` | ERP 基础资料、采购、销售、库存、财务以及端到端业务闭环。 |
| `03-工作流操作手册.md` 至 `14-即时通讯操作手册.md` | 分别覆盖 BPM、会员、支付、商城、CRM、报表、公众号、AI、IoT、MES、WMS、IM 等模块。 |

文件编号提供稳定的阅读顺序；模块文件独立可读，避免将所有功能堆入单一超长手册。

## 3. 编写标准

每份模块手册采用一致章节：

1. 适用角色与功能概览。
2. 前置数据、菜单权限和外部服务依赖。
3. 功能菜单与业务对象说明。
4. 可复现的操作步骤，包含关键字段、保存或提交动作及预期结果。
5. 状态流转、撤销或删除限制、数据关联和权限边界。
6. 常见异常、核查路径和操作注意事项。

ERP、CRM、商城、MES 和 WMS 额外描述主数据准备顺序，以及从单据创建到审核、出入库或结算的典型业务闭环。
涉及审批的模块同时说明发起、待办、通过、驳回和撤回的责任边界。

## 4. 事实核验与启动边界

实现前先检查当前后端与前端进程、端口和日志；服务未运行时，使用项目现有启动脚本启动并确认前端可访问。
核验以菜单路径、前端视图、接口定义和实际页面访问为准。发现数据库表、第三方凭据或外部服务缺失时，
在手册中如实记录为前置条件或限制，不通过修改业务代码掩盖问题。

本次交付为 Markdown 文档，不修改业务功能、数据库或运行配置。启动服务仅用于验证和采集操作依据。

## 5. 验收标准

1. `docs/README.md` 可定位到所有模块手册。
2. 每个已启用模块均有对应操作说明，不存在空模板、TBD 或虚构菜单。
3. 所有中文 Markdown 文件使用 UTF-8，标题、表格和文件链接可正常显示。
4. 文档中的菜单、关键流程和依赖限制可由项目源码或运行环境交叉验证。
5. 对外部集成能力清楚标示启用条件、风险和不可用时的替代操作。

## 6. 风险与处理

运行环境此前日志记录过 IoT 表缺失等数据库问题。文档将区分“功能设计的标准操作”与“当前环境未满足的前置条件”，
避免将环境故障误写成正常系统行为。若无法完成启动，将利用路由、接口和页面源文件完成静态核验，并明确记录未做的
运行验证。
